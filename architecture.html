Data Flow — Filter Change Propagation
1
User updates a filter
FilterBar.vue — dropdown v-model updates the composable's reactive ref.
selectedLocation.value = "London" // in useFilters()
2
Singleton composable notifies watchers
useFilters.js is a singleton — the same reactive state is shared across all views. Any watch() subscribed to it fires immediately.
// Every view watches filter state watch([selectedPeriod, selectedLocation, ...], loadData)
3
View calls API with current filters
The active view calls getCurrentFilters() then delegates to api.js.
const filters = getCurrentFilters() // { warehouse: "London", ... } const data = await api.getInventory(filters)
4
Axios builds and fires HTTP request
api.js encodes filters as query params on the URL.
GET http://localhost:8001/api/inventory?warehouse=London&category=all
5
FastAPI filters in-memory data
apply_filters() iterates the in-memory list loaded at startup, returning only matching items.
filtered = [i for i in inventory if i["warehouse"] == "London"] return [InventoryItem(**i) for i in filtered] # Pydantic validates
6
Pydantic serializes response
Response models enforce field types before JSON is sent. Unknown fields are stripped.
class InventoryItem(BaseModel): id: str; sku: str; warehouse: str; quantity_on_hand: int ...
7
Vue component updates reactive state
The resolved Axios promise updates a ref, triggering computed property recalculation.
inventoryItems.value = response.data // triggers computed re-eval
8
DOM re-renders with filtered data
Vue's reactivity system diffs and patches only the changed table rows — user sees London-only items with no page reload.

Key Design Patterns
Frontend Patterns
S
Singleton Composable (useFilters)
Filter state lives in a module-level singleton so all views share the same reactive refs without Pinia or Vuex.
C
Raw Refs + Computed Derived Data
Raw API data is stored in refs (allOrders, inventoryItems). All derived views are computed properties — never mutate raw data.
W
Watch-Triggered Data Loading
Every view watches the filter composable. When any filter changes, loadData() fires automatically — no event bus needed.
M
Centralized API Layer
api.js is the only file that knows the backend URL. All views call named methods (getInventory, getOrders) — never raw axios calls.
Backend Patterns
R
Pydantic Response Models
Every endpoint declares a response_model. Pydantic validates and strips unexpected fields before JSON is serialized — type safety end-to-end.
F
Reusable Filter Utilities
apply_filters() and filter_by_month() are shared helpers. Quarter→month expansion (Q1-2025 → ['2025-01', '2025-02', '2025-03']) lives in QUARTER_MAP.
I
In-Memory Data Store
All JSON files are loaded once at startup by mock_data.py. Queries use list comprehensions in Python — zero database latency.
A
Aggregation at Endpoint Level
Dashboard summary endpoint computes totals (total_inventory_value, low_stock_items) from raw data on every request — no separate aggregation layer needed.
